# Investigation test-design review

## Verdict and findings

**PASS for test design.** `construction-plan.md` covers R1–R13 through requirement coverage, Given/When/Then cases, invariants, error cases, implementation units, and TDD order. Its tests address the findings below. B1–B15 provide the detailed observable assertions and numeric oracle for those planned cases. There is no remaining blocking test-design finding. Construction and runtime verification remain pending; this review changes documentation only and does not claim new passing runtime tests.

| Finding | Evidence | Required test-design correction |
| --- | --- | --- |
| Shared raw delta can accidentally inherit Web presentation rounding. | `web/src/model/rework-comparison.test.ts`, “keeps direction consistent with one-decimal delta display precision,” expects delta `0` for `5000/10000` to `5004/10000`. The accepted design requires unrounded shared results. | B4 fixes the shared delta oracle at approximately `0.04` percentage points and separately checks Web display `0.0` and unchanged direction. Do not transfer the old rounded-delta expectation into Go or MCP. |
| The existing all-five test checks only two explicit denominator pairs. | The same test file, “compares all five normalized diagnostics with their desired direction and evidence,” asserts the first baseline denominator and last current denominator. | B3 checks every metric's identity, unit, both numerators/denominators, values, raw delta, and availability through both public transports against an independently stated expected result. |
| Dedicated aggregate comparison compatibility tests are absent from the audited baseline. | `compatibility-audit.md`; no `compare_runs` case in the inspected `internal/transport/mcpserver/server_test.go`. | B6 exercises actual MCP requests for one and ten runs, cross-source and overlapping runs, default and selected dimensions, and invalid cardinalities. |
| Exact-span handling needs assertions beyond URL serialization or a trace-level link. | Existing navigation and app tests cover conversation anchors and return routing. The task adds trace anchors, missing targets, purpose state, and every episode. | B1/B2 assert visible exact selection, content, missing-target identity, and restored origin through user actions. |
| Saved-state failure and coverage distinctions need separate observable states. | Accepted R5/R11; compatibility audit distinguishes retained projections, page limits, and content defaults. | B9–B14 cover unsupported/corrupt saved data, failed mutations, partial/filtered/missing trace states, provider provenance, and body exclusion. |

The reviewed baseline locations are [comparison tests](https://github.com/kotokumu/agentmetry/blob/main/web/src/model/rework-comparison.test.ts), [app behavior tests](https://github.com/kotokumu/agentmetry/blob/main/web/src/app/agentmetry-app.test.ts), [navigation tests](https://github.com/kotokumu/agentmetry/blob/main/web/src/app/navigation.test.ts), [SQLite tests](https://github.com/kotokumu/agentmetry/blob/main/internal/storage/sqlite/store_test.go), [Connect tests](https://github.com/kotokumu/agentmetry/blob/main/internal/transport/connectapi/server_test.go), and [MCP tests](https://github.com/kotokumu/agentmetry/blob/main/internal/transport/mcpserver/server_test.go). The matrix below identifies test levels rather than prescribing new files or private methods.

## Invariants and testability

| Invariant | Example | Expected Result |
| --- | --- | --- |
| Identity survives every boundary. | Same conversation ID under two sources; several failed spans in one trace. | Requested source/conversation/trace/span is never substituted. |
| Measurement evidence and presentation remain separate. | Raw delta `0.04`; display rounds to one decimal. | Public values stay unrounded; only presentation changes. |
| Missing, zero, partial, raw-only, and filtered are not synonyms. | Full analyzed projection, absent body, filtered selected span. | Independent states remain observable. |
| One comparison uses coherent retained evidence. | Concurrent commit changes token total or time extent. | Both conversation values, denominators, coverage, and eligibility belong to one coherent read. |
| Content access cannot be bypassed through evidence metadata. | Unique body sentinel in a comparison fixture. | Non-opt-in responses contain no sentinel in any field. |

- Interface concern: a transport-only comparison test using an already fabricated report cannot prove both clients read the same pair or snapshot. Include one seeded-storage path through each public handler.
- Responsibility concern: expected metrics must be explicit fixture facts or independently calculated constants, not results of the same implementation under test.
- Coupling concern: assert public query outputs, protocol responses, URLs, visible selection/content, and focus. Avoid private helper calls, exact internal call order, and tests that merely confirm framework composition.
- Verification scope: the behavior cases are required before their task checkboxes close. The existing Go, integration-tag, Vitest, build, synthetic browser, and strict OpenSpec checks in tasks 9.1–9.3 remain the final validation plan.
